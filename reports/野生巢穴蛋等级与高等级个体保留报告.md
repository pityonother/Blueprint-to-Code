# ARK 野生巢穴蛋等级与高等级个体保留报告

> 范围：野外固定巢点生成、主要靠偷蛋获得的飞龙（Wyvern）、熔喉龙（Magmasaur / Cherufe）和恐爪龙（Deinonychus）。
>
> 分析基线：本地 ARK DevKit 当前 `.uasset`、当前 `ShooterGameEditor-ShooterGame.dll` / PDB 符号，以及 ARK Official Community Wiki 的玩法资料。本文把“蓝图已确认”“图链接推断”和“仍需服务器实测”分开写。

## 一句话结论

**保留高等级野生个体是有效策略，但不是“排队轮到它就必出蛋”的保证。**

当前三条蓝图都是由野生个体自己的 `SpawnNestEgg` 创建巢穴，然后对当前个体 `self` 调用 `CreateCloneFertilizedEgg`。巢穴类没有再随机抽取一次蛋等级。因此，玩家观察到“某只野生龙的等级、颜色与巢中蛋对应”，在当前资产结构上不是巧合，而是符合创建链的结果。

不过刷新不是一个全局轮盘：每只仍存在的个体只在满足冷却、进入过 stasis 后重新 unstasis、附近存在可用巢点且巢点未被占用等条件时尝试。失败也可能消耗这一轮冷却。所以正确表述是：

> 留住高等级个体，会保留这个等级以后再次产巢蛋的来源，并显著提高你反复获得该等级蛋的机会；它不会保证下一轮或某一固定轮次必定出现该等级。

## 1. 蛋等级究竟看什么

### 1.1 当前可确认的创建链

三种生物的流程结构相同：

```text
野生个体 BPUnstasis
  -> 检查个体自己的上次产巢时间与冷却
  -> 仍未再次 stasis
  -> SpawnNestEgg
  -> 找到距离该个体最近的地图标记巢点
  -> 检查距离、已有同类巢数、地面射线与服务器开关
  -> SpawnActor(NestToSpawn)
  -> self.CreateCloneFertilizedEgg(...)
```

关键点有三个：

1. `CreateCloneFertilizedEgg` 的 `self` 引脚没有连接其他对象。在成员函数调用中，这表示调用者就是正在执行 `SpawnNestEgg` 的当前野生个体。
2. 三个 `SpawnNestEgg` 图里都没有“为蛋重新随机等级”的节点。熔喉龙图中的 `RandomIntegerInRange` 用来选巢穴网格 socket，不是抽蛋等级。
3. 原生 PDB 中存在精确符号 `APrimalDinoCharacter::CreateCloneFertilizedEgg`，不是由巢穴对象调用的独立随机蛋函数。

本轮确认了 Blueprint 调用目标和当前 PDB 中的原生 API 身份，但没有把 `CreateCloneFertilizedEgg` 的完整 C++ 函数体作为已发布证据。因此，“等级来自当前个体”是由 `self` 调用、API 语义、巢穴无等级计算和玩家可复现实测共同支持的强结论；若要逐字段证明颜色、全部属性点和 traits 如何写入蛋，还需要针对当前 DLL 的受限原生反编译或服务器受控样本。

因此，当前证据支持：

- 蛋的生物等级/野生属性来源是执行创建的那只野生个体。
- 蛋的种类由个体的 `FertilizedEggItemsToSpawn` 和对应巢穴类限定。
- 地图难度与该物种自己的野生等级阶梯先决定能生成怎样的野生个体；蛋再复制实际执行产巢的个体，而不是巢穴另抽一个难度等级。
- ASA 的基因特质不能简单等同于“完整复制”。当前调用可见 `AddGeneTraits`、`CopyGeneTraits` 两个独立参数；熔喉龙和恐爪龙当前调用默认是新增特质而不是直接复制特质。本文的“同等级来源”不等于“所有 trait 必然相同”。

### 1.2 巢穴自己不决定等级

`WyvernNest` 及其子类 `CherufeNest`、`DeinonychusNest` 只保存“附近应当存在什么蛋类”的引用。基础巢穴在服务器端每 60—120 秒检查一次附近是否还有匹配的蛋；数量为 0 时销毁自己。

这说明巢穴主要负责承载和清理：

- 飞龙巢检查 `DroppedItemGeneric_FertilizedEgg_NoPhysicsWyvern_C`；
- 熔喉龙巢检查 `DroppedItemGeneric_FertilizedEgg_NoPhysicsCherufe_C`；
- 恐爪龙巢检查 `DroppedItemGeneric_FertilizedEgg_NoPhysicsDeinonychus_C`。

巢穴图中没有野生等级、难度、随机等级或附近生物等级的计算。因此，“巢先随机一个等级，再找同等级龙配上去”的模型不符合当前资产。

## 2. 保留高等级野生个体，后面还能不能继续出同等级蛋

### 2.1 能：因为产蛋来源仍然存在

只要那只高等级个体没有死亡、被系统清理或被 `DestroyWildDinos` 一类操作消灭，它以后再次进入产巢执行链时，仍然会以自己作为 `CreateCloneFertilizedEgg` 的源对象。这就是保留策略有效的机制原因。

三种生物的产巢入口都挂在 `BPUnstasis`，入口还会排除已驯服个体。换成玩家语言就是：

- 你离开足够远，让区域和生物进入 stasis；
- 等待该个体的产巢冷却；
- 再次进入区域，使其 unstasis；
- 它才有机会重新跑一次产巢检查。

**一直站在沟里持续渲染它，不等于不断触发新一轮。** 对这三条当前蓝图来说，离开—等待—回来的 unstasis 周期比原地死等更符合触发机制。

### 2.2 不能保证：这里没有“后续轮到它”的队列

蓝图没有保存一个“上轮 150、下轮 180”的等级轮换表，也没有全局 round-robin 队列。每只个体各自检查、各自找最近巢点，以下任何一项都会让本次失败：

- 冷却尚未结束；
- 回到区域后三秒的延迟结束前又进入 stasis；
- 该地图没有有效的对应巢点列表；
- 最近巢点距离个体太远；
- 检查半径内已有同类巢穴达到上限；
- 地面射线没有得到可生成位置；
- 驯服/默认驯服禁用开关使该链提前返回；
- 其他同类个体先占用了有限巢点；
- 高等级个体死亡、落岩浆、被刷掉、被野怪杀死或服务器执行野生龙清除。

事件图的顺序还显示：到达冷却后，会先更新本个体的时间戳，再调用 `SpawnNestEgg`。所以即使后面的巢点检查失败，本轮时间也可能已经记账，不会立刻无限重试。

### 2.3 不要只凭“雌性”筛选

在本次检查到的三条 `BPUnstasis -> SpawnNestEgg -> CreateCloneFertilizedEgg` 链中，没有看到 `bIsFemale` 性别门槛。飞龙资产里确实有雌性产奶逻辑，但它是另一条链。

因此，实践中应以“等级、元素/种类、位置、是否仍存活”标记候选个体，不要因为它显示为雄性就先认定它绝不可能是巢蛋来源。性别之外的地图生成规则仍可能影响种群，但当前产巢图本身没有按性别过滤。

## 3. 三种生物的具体差异

| 项目 | 飞龙 | 熔喉龙 | 恐爪龙 |
|---|---:|---:|---:|
| 地图巢点标签 | `DragonNestSpawns` | `MagmasaurNestSpawns` | `DeinonychusNestSpawns` |
| 个体到巢点最大距离 | 30,000 uu（约 300 m） | 100,000 uu（约 1,000 m） | 15,000 uu（约 150 m） |
| 检查同类巢穴半径 | 2,000 uu（约 20 m） | 10,000 uu（约 100 m） | 2,000 uu（约 20 m） |
| 半径内允许同类巢数 | 1 | 2 | 1 |
| 个体产巢冷却 | 6,000 秒（100 分钟） | 5,000 秒（83 分 20 秒） | 5,000 秒（83 分 20 秒） |
| 偷蛋警戒邻居范围 | 30,000 uu | 30,000 uu | 15,000 uu |
| 时间变量 | 复用 `LastBeaverDamSpawn` | `LastEggSpawnTime` | `LastEggSpawnTime` |

说明：uu 到米采用 Unreal 默认的 100 uu ≈ 1 m，仅用于帮助理解尺度。地图 Mod、子类覆盖或服务器版本差异可以改这些值。

### 飞龙

- 基础飞龙类启用 `bSpawnNestEgg=true`。
- 火、雷、毒等子类通过自己的 `FertilizedEggItemsToSpawn` 选择蛋类型；因此元素类型也来自实际执行的飞龙子类。
- 当前基础类用 6,000 秒的 `UnstasisStructureCreateDamInterval` 作为产巢间隔，变量名是海狸坝系统遗留命名，不代表它真的在造坝。
- 官方社区资料说明普通生物通常有 30 个野生等级档，飞龙有 38 个档；官方难度 5 时蛋最高可到 190。这是“野生飞龙可生成等级阶梯”的差异，不是巢穴额外加 40 级。[Wyvern Egg](https://ark.wiki.gg/wiki/Wyvern_Egg)

### 熔喉龙

- 使用 `MagmasaurNestSpawns`，允许在 100 m 检查范围内最多存在 2 个同类巢，搜索个体附近巢点的最大距离也明显大于另外两种。
- 当前冷却为 5,000 秒。
- 官方社区资料列出的官方难度最大蛋等级是 150；实际仍受服务器难度和覆盖设置影响。[Magmasaur Egg](https://ark.wiki.gg/wiki/Magmasaur_Egg)

### 恐爪龙

- 使用专门的 `UnstasisStructureCreateEggInterval=5000`，不是复用海狸坝变量。
- 当前巢点最大距离只有约 150 m、同类巢检查半径约 20 m；把高等级恐爪龙引得太远，会直接失去可用巢点。
- 官方社区页面也提供了查询地图上未拾取恐爪龙巢蛋的管理员命令，可用于私服诊断，但普通刷蛋不需要依赖命令。[Deinonychus Egg](https://ark.wiki.gg/wiki/Deinonychus_Egg)

## 4. 最有效的高等级保留刷蛋法

### 普通玩家流程

1. **先记录候选个体。** 记下等级、元素/种类、颜色、GPS 大致位置；不要只记“附近有一只 180”。
2. **取走所有低等级蛋。** 取蛋后让对应巢穴在下一次 60—120 秒检查中因无蛋而清理，给后续巢点腾位置。不要只看一眼后把低级蛋留在原巢。
3. **清低保高。** 击杀低等级同类，但不要误杀高等级候选，也不要执行全图野生龙清除。
4. **让高等级个体留在有效巢区。** 尤其恐爪龙不要引离对应巢点超过约 150 m；不要让飞龙或熔喉龙掉进岩浆/地形死角。
5. **离开渲染范围。** 让它进入 stasis，而不是一直在旁边等。
6. **等待完整个体冷却。** 飞龙约 100 分钟；熔喉龙和恐爪龙约 83 分 20 秒。为了排除计时误差，实测可多留 5—10 分钟余量。
7. **重新进入并检查最近巢点。** 同时确认候选个体仍在；若没有蛋，不要立刻断言机制无效，先排查巢占用、距离、地形与是否真的经历 stasis。
8. **重复记录至少 5—10 轮。** 记录每次候选是否存在、进入时间、蛋等级、巢位置。这样可以区分“个体没机会执行”与“执行后被别的个体抢了巢点”。

### 最干净的私服验证

如果你有自己服务器的管理权限，最有说服力的实验不是直接召唤蛋，而是：

1. 只保留一只已记录的高等级目标个体；
2. 清空该区域现有蛋和巢，但不清除目标个体；
3. 确认目标仍在有效巢点距离内；
4. 离开区域、等待完整冷却、再返回；
5. 连续重复并对比新蛋的等级/元素。

这个实验直接检验“同一个体能否多轮产出”，比一次看到同等级龙和蛋更强。不要使用 `DestroyWildDinos`，因为它会同时消灭你要保留的来源。

## 5. 已确认、推断与未确认边界

### 已确认

- 三种个体均有 `SpawnNestEgg`，且启用 `bSpawnNestEgg=true`。
- 三者均在产巢图中调用 `CreateCloneFertilizedEgg`。
- 调用目标是当前个体 `self`，没有连接其他生物对象。
- 巢穴类不计算蛋等级，只检查匹配蛋是否仍存在并在无蛋时自毁。
- 三种个体各自的巢点标签、距离、巢数上限和冷却值如上表；`BPUnstasis` 入口检查 `BPIsTamed`，这条巢蛋链针对野生个体。
- 产巢入口来自 `BPUnstasis`，不是持续轮询的全局蛋等级队列。

### 高可信图结构推断

- 同一只个体在以后新的 unstasis 周期中可以再次尝试产巢，因此“保留高等级来源”有效。
- 失败尝试也可能先更新个体时间戳，故不会立即重试。
- 多只个体竞争有限巢点时，不存在按等级轮换的保证。

### 本报告不声称

- 不声称下一轮必定是保留个体的蛋。
- 不声称蛋的所有 ASA Gene Traits、突变或每个颜色区都必然逐项复制；当前调用把 traits 作为单独参数处理。
- 不声称 Mod 地图、非官方子类或未来补丁一定沿用同一冷却与距离。
- 不把单次“龙和蛋同等级”的观察当作概率结论；本地创建链才是主要证据，玩家观察用于验证。
- 不声称本轮已经逐字段反编译 `CreateCloneFertilizedEgg` 的完整原生函数体。
