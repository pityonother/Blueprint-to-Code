# Blueprint to Code v0.3.2 — Integrated Windows Portable Engineering Preview

## 发布定位

```text
RELEASE_TYPE=ENGINEERING_PREVIEW_SOURCE_AND_WINDOWS_PORTABLE
```

v0.3.2 把截至 2026-08-26 已完成、可归因并通过合并审计的功能整合到同一个
`main` 候选中。稳定入口、实验性 source-contract preview 与仍未取得 production
authority 的 shadow 能力在下面分开列出，避免“代码已包含”被误解为“生产切换已完成”。

## 普通用户应该下载哪个文件

请下载：

```text
BlueprintToCode-v0.3.2-windows-x64-portable.zip
```

同一 Release 会提供 `.zip.sha256`。不要下载 `Source code (zip)` 或
`Source code (tar.gz)` 来直接使用；它们是 GitHub 自动生成的开发者源码归档，不含
预构建网页和内置运行时。

完整解压后双击 `START_HERE.bat`。便携包包含预构建网页与核验来源的 Python
3.13.13 Windows x64 embeddable runtime，不需要安装 Python，也不需要安装 Node.js。

## v0.3.2 新增的正式可用入口

### ShooterCharacter 下蹲属性只读反射

- 控制中心现在识别 `/Script/ShooterGame.ShooterCharacter`，不会再把它改写成
  `/Game/Mods/Script/...`，也不会搜索不存在的 `.uasset`。
- 工具通过本机 ARK DevKit 的官方 PythonScriptCommandlet 做一次只读反射；已在
  DevKit `92.35.288.826107` / Unreal `5.5.4-0+UE5` 上真实验收。
- `bIsCrouched` 与 Python 暴露名 `is_crouched` 都可读，声明来源为继承的
  `Character`；类默认对象值为 `false`。`crouch`、`un_crouch`、
  `on_start_crouch`、`on_end_crouch` 也均可见，但探针不会调用它们。
- 返回契约固定标记 `CLASS_DEFAULT_OBJECT_ONLY`、
  `runtimeStateAvailable=false` 和 `readOnly=true`。

准确边界：这能确认 ShooterCharacter 有可查询的下蹲属性，并读取类默认值；它不是
在线玩家实例的实时监测。要判断某个玩家此刻是否下蹲，仍需在游戏或 PIE 中取得该
玩家实例后读取运行时值。

### authoritative Evidence 与研究编排

- authoritative Evidence cohort 发布、同一 source generation 绑定、freshness 与
  formal-query gates，以及控制中心的权威就绪状态。
- exact pin link identity、深层图作用域、精确 Class Defaults、稳定 `bp://` 身份和
  有预算的 Evidence 查询。
- runtime loot 查询与组合路线，可把 Blueprint 入口、native boundary 与已有
  Native Evidence 按明确缺口组合起来。
- privacy-safe requirement solver：把 ARK 问题编译为 evidence-backed research
  plans，同时隔离私有请求原文与共享任务目标。
- ARK Registry taxonomy pilot、unknown-name cluster 采样、bounded native recipe、
  category routing、风险分级验证收据和统一交付 manifest。

## 已包含但仍保持实验/影子边界的能力

### ARK DevKit Editor Bridge

只读 Editor Bridge、Evidence 到节点的精确绑定、Tasks/Plans 与 editor-state
snapshot 源码已经合并，但发布身份仍是 **source-contract preview**。本机没有可用的
ARK DevKit C++ 插件构建环境，因此没有声称该 Bridge 已完成插件编译或真实编辑器
runtime acceptance；便携包中的这部分是可审查源码合同，不是稳定 live 功能。

### Knowledge Base additive backends

Selective Role/Domain rebuild、逐投影发布、narrow-gated additive shadow publisher
及其恢复/收据合同已经整合。它们没有切换生产查询：本版本继续保持
`mode=shadow`、`defaultQuerySource=legacy`、`cutoverEligible=false`，也不会修改
live KB pointer。

## ARK DevKit 与分发边界

打开网页和本地服务不要求 ARK DevKit；读取新的 `.uasset` / `.uexp` 或运行
`/Script` 原生类探针时，用户电脑必须合法安装 ARK DevKit。工具会先读取 Epic
Games Launcher 清单自动定位，失败时再使用 `devkit_content_root.txt`。

便携包明确：

- 不包含 ARK 数据、游戏资产或 DevKit；
- 不包含 ARK/ShooterGame DLL/PDB；只包含启动所需且来源核验的 Python runtime
  DLL/PYD；
- 不包含 Capture/Evidence DB、真实 runtime observations、Harvest 数据库、
  Knowledge Base、Native Evidence、Ghidra workspace、本机路径、凭据或日志；
- 用户自己的输出只会在解压后的本地目录中生成。

## 完整性与已知限制

- 外部 `.zip.sha256` 提供整个下载文件的 SHA-256，包内 `SHA256SUMS.txt` 绑定逐文件内容；
- `PACKAGE_MANIFEST.json` 绑定版本、Git commit、平台、文件数和 runtime 来源；
- 发布前必须通过源码内容扫描、完整 Python/前端测试、依赖审计、Windows 便携包
  全新解压启动和 HTTP smoke test；
- 这是 Engineering Preview，不是完整 Blueprint decompiler，不恢复开发者原始 C++；
- 便携 ZIP 尚未做 Authenticode 签名，默认服务仅监听 `127.0.0.1:8765`；
- confirmed interpretation 必须保留 Evidence trace，缺失来源继续标为 gap、
  `HEURISTIC`、`NOT_RECOVERED`、`SOURCE_NOT_AVAILABLE` 或 `AMBIGUOUS`。
