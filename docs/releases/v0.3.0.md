# Blueprint to Code v0.3.0 — Engineering Preview

## 发布定位

v0.3.0 是 Blueprint 与 Harvest 两条核心链路的 Engineering Preview。发布类型为：

```text
RELEASE_TYPE=ENGINEERING_PREVIEW_SOURCE_ARCHIVE_ONLY
```

它提供可审查、可测试的工程合同，不把静态推导包装成真实游戏运行结果，也不表示
ARK Knowledge Base 已满足生产切换条件。

## Blueprint

- Evidence Publication v3 以不可变 revision、原子 `current.json` pointer、manifest
  hash 和来源身份约束 validated readers；
- bounded Evidence queries 只返回预算内、可追踪的证据；
- Interpretation Contract v1 提供确定性的控制流、数据流、statement trace 和
  explicit gaps；
- heuristic behavior hints、名称、注释与未确认 defaults 会降级，不会成为 confirmed
  behavior；
- legacy/experimental pseudocode 只是 Evidence-derived review aid，不是恢复出的原始
  C++；
- Blueprint workspace 已拆分为明确的 frontend、HTTP route、publication 与
  interpretation 模块。

## Harvest

- dominance audit 对候选结果执行支配关系检查；
- confirmed 与 conditional 榜单分离，conditional 不会混入 confirmed tier；
- canonical variant、metric-specific units 与 static total/static cycle/observed
  语义分别呈现；
- runtime profile isolation 阻止跨 profile 的 observed 比较；
- relative-first specialties 与 Effectiveness gap 明确展示“可证明”与“尚缺证据”的
  边界；
- Harvest build、ranking、HTTP 与 frontend 使用明确的模块边界。

## 工程与分发

本次分发合同是 `SOURCE_ARCHIVE_ONLY`。唯一允许的发布资产是 GitHub 对候选 Git
ref 自动生成的：

- Source code (zip)
- Source code (tar.gz)

发布内容扫描、凭据扫描、绝对路径扫描与生成物扫描必须针对同一个候选 ref 通过。
DevKit exporter 不再包含本机用户路径，项目根目录按以下顺序解析：

1. `BLUEPRINT_TO_CODE_ROOT`；
2. 从 plugin base 向上寻找 `scripts/bp_clipboard_to_prompt.py`；
3. 当前用户的 `Documents/Blueprint to Code` fallback。

## 明确不包含的内容

- 不包含 ARK 数据
- 不包含 DevKit
- 不包含 DLL/PDB
- 不包含 Capture/Evidence DB
- 不包含真实 runtime observations
- 不包含 Ghidra workspace、runtime bundle、full environment、Harvest database、
  Native Evidence 或 Discovery database

## 已知限制

- 这是 Engineering Preview，不是完整 Blueprint decompiler，也不会恢复开发者的
  原始 C++。
- confirmed interpretation 必须保留 Evidence trace；不能追踪的内容会成为 gap、
  `HEURISTIC`、`NOT_RECOVERED`、`SOURCE_NOT_AVAILABLE` 或 `AMBIGUOUS`。
- public Native Fixture 只能证明公开 fixture pipeline；它不证明 ARK proprietary
  binary，也不代表真实 ARK runtime 行为已经验证。
- [report registry](../../reports/report_registry.json) 的 release-candidate summary
  为 `ACTIVE_FORMAL=0`、`historical errors=3`、`historical warnings=3`、
  `DIAGNOSTIC=6`。3 份缺少 native provenance 的历史 report 继续保留为
  `HISTORICAL_PROVENANCE_INCOMPLETE`；这些错误不会被改写成 verified，也不会进入
  active formal claims。
- ARK KB 继续保持 `mode=shadow`、`defaultQuerySource=legacy`、
  `cutoverEligible=false`。v0.3.0 不切换 live KB pointer。
