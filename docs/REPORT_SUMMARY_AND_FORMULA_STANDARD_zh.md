# 报告总结与公式提取标准

这份文档是全项目通用标准，适用于任何 ARK DevKit 蓝图资产，不只适用于某一只生物或某一个物品。

目标是让每次读取蓝图后，报告不要只停留在“读到了多少节点”，而是进一步变成小白也能理解、玩家也能使用、后续知识库也能复用的结论。

## 总结报告应该怎么写

每个资产报告总结按这个顺序写：

1. 这个蓝图在游戏里负责什么。
2. 玩家、服主或模组分析者能从它得到什么收益或风险。
3. 关键机制由哪些图页、默认值、变量、函数调用支持。
4. 哪些地方能整理成明确规则或公式。
5. 哪些地方还只是可见逻辑，不能写成最终公式。
6. 下一步只补最相关的 1-3 个资产、函数或图页。

回答玩家问题时，先讲操作和收益，再讲证据。不要一上来把用户丢进节点名、Pin 名和内部函数名里。

## 哪些内容要转成候选公式

只要报告或蓝图里出现下面这些类型，就要尝试提取成“候选公式、规则表或条件链”：

- 概率：成功率、失败率、继承概率、掉落概率、随机权重、Random、Chance、Weight。
- 属性：生命、耐力、氧气、食物、重量、近战、速度、眩晕、属性点、等级、成长、驯养效率。
- 上下限：Min、Max、Clamp、Cap、Limit、Threshold、Range。
- 时间：冷却、持续时间、间隔、倒计时、Buff tick、Timer。
- 收益：XP、经验倍率、宝箱、掉落池、奖励数量、品质范围。
- 消耗：资源消耗、耐久、次数、堆叠、使用条件。
- 战斗和状态：伤害、治疗、减伤、倍率、抗性、Buff/Debuff 强度。
- 数学节点：加减乘除、MapRange、Lerp、Curve、Normalize、Select、Branch 条件。

“候选公式”不是最终答案。它只是提醒我们：这里有数值机制，应该继续从 Class Defaults、图页节点、Pin 默认值、关联资产里找证据。

## 什么时候可以写成明确公式

满足这些条件时，才可以把内容写成明确公式：

- 数值来自当前资产的 Class Defaults、节点默认值、Pin 默认值、结构体字段或已解析的关联资产。
- 执行流和数据线足够清楚，不是严重依赖 `pin_links_heuristic`。
- `capture_quality_report.md` 没有要求补采当前关键图页。
- `diagnostics_report.md` 没有指出关键函数是未知本地图页。
- 公式不依赖看不到函数体的 native/C++ 或父类实现。

写公式时要同时写证据来源，例如：

```text
公式：最终倍率 = BaseMultiplier * BuffMultiplier
证据：Class Defaults 里的 BaseMultiplier；图页 ApplyBuff 中的乘法节点和 BuffMultiplier Pin。
可信度：高 / 中 / 低
```

## 什么时候不能写成最终公式

遇到这些情况，不能把结果写死成最终公式：

- 关键函数是 native/C++，例如只看到函数名，看不到函数体。
- 关键逻辑在父类、组件、宏、collapsed graph、delegate 或 timeline 里，还没读到。
- 图页不完整，或者 Pins/LinkedTo 没恢复。
- 只能看到调用点，看不到被调用函数内部。
- 数值是资产引用、枚举或结构体索引，但还没有解析到真实资产或字段含义。

这种情况要写成：

```text
已知可见部分：当前蓝图会调用 X，并把 A、B、C 作为输入。
不能确定部分：X 的内部公式不在当前蓝图资产里。
当前结论：不能给最终公式，只能记录为 unresolved_formula。
下一步：读取父类/关联资产，或用 DevKit/游戏内样本做回归验证。
```

## 可信度标签

建议每个公式或规则都带一个可信度：

- `high`：节点、Pin、默认值、连线都能对应，且不依赖外部未知函数。
- `medium`：主要逻辑能看到，但部分资产引用、边界条件或启发式连线还需要验证。
- `low`：只能看到名字、调用点或部分输入，不能对玩家给精确数值。
- `unresolved_formula`：明确知道这里有公式，但公式主体在 native/父类/未读资产里。

看到 `low_confidence` 时，不要给玩家写精确公式。可以写“可见部分”和“缺失部分”。

## 推荐输出格式

每个重要机制可以按这个格式写：

```text
机制：羽毛继承概率
玩家意义：决定羽毛偏向影响哪一项属性继承。
可见规则：羽毛属性与被拔毛个体的最高属性有关。
候选公式输入：最高属性点、属性枚举、native 函数返回权重。
已知证据：图页调用 GetDinoStatDistributionAgainstMax。
缺口：GetDinoStatDistributionAgainstMax 是 native/父类逻辑，当前资产看不到内部公式。
可信度：medium，用于方向判断；unresolved_formula，用于具体数值。
下一步：读取父类/native 线索，或导出 30/40/50 点样本做回归。
```

这个例子来自巨盗龙，但格式适用于所有蓝图。

## 写入知识库时的要求

导入知识库时，公式相关内容不要只写自然语言。至少要拆成：

- `mechanism`：机制名。
- `player_meaning`：玩家视角意义。
- `visible_rule`：当前蓝图可见规则。
- `formula_candidate`：候选公式或输入输出关系。
- `evidence`：来自哪些报告、图页、默认值或函数调用。
- `confidence`：可信度。
- `unresolved_dependencies`：native、父类、关联资产、缺图。
- `next_probe`：下一步应该读什么。

这样后续扫描新资产时，才能自动判断“这个公式已经解决了”还是“这个公式还只是候选”。
